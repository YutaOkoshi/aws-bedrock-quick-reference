## User Story

**As a** 推論先を根拠付きで説明する必要がある開発者・コンプライアンス担当者
**I want** 表の行を開いて、使い方（In-Region / Geo / Global）を 1 つずつ切り替えながら、データがどこへ行き記録がどこに残るかを見たい
**So that** 「このモデルをこう使うと国の外に出るか」という問いに、1 画面・1 図で答えられる

## Acceptance Criteria

### AC-001 (行の展開)
- **Given**: 「起点から」ビューの表が描画されている
- **When**: 行の展開操作（行クリックまたは展開トグル）を行う
- **Then**: その行の直下に詳細パネルが開く。他の行は閉じたままでも複数同時に開けてもよいが、展開状態は起点リージョンを切り替えても対象モデルが表に残っている限り保持する

### AC-010 (パネル共通の見出し行)
- **Given**: 起点リージョン R でモデル M の行を開く
- **When**: 詳細パネルを描画する
- **Then**: パネルの先頭に、レーンによらず共通の見出し行が出る。中身は次の 2〜3 項目で、2 列のグリッド（375px では 1 列）に並ぶ
  1. **モデル ID**: M のモデル ID とコピーボタン。クリップボードには ID の文字列だけが入る
  2. **接続先 (bedrock-runtime)**: R の FQDN（例: `bedrock-runtime.ap-northeast-1.amazonaws.com`）。起点を切り替えると値も切り替わる
  3. **接続先 (bedrock-mantle)**: R に mantle があるときだけ出る行。FQDN・呼べる API・Mantle で指定するモデル ID・cross-region inference が使えない旨の注記・出典リンク（MANTLE-001 AC-005 / AC-006）。R に mantle が無いときはこの項目ごと出さない
- **And**: TABLE-001 が表から外した識別子は、必ずここから辿れる

### AC-014 (レーンのタブと常時見える要約)
- **Given**: 起点リージョン R でモデル M の行を開く
- **When**: 見出し行の下を見る
- **Then**: `role="tablist"` のタブが **In-Region / Geo / Global** の 3 つ並ぶ。各タブは 2 行で、上が見出し、下が**常に見える 1 行の要約**

  | レーン | 見出し | 要約 |
  |---|---|---|
  | In-Region | `In-Region` | 可のとき「国内に留まる」（en: `Stays in country`）。不可のとき「提供なし」（en: `Not available`） |
  | Geo | `Geo（＜地理圏名＞）`。プロファイルが複数あるときは地理圏名を「 ・ 」で連ねる | 「国内 N ・ 国外 M」。**M ≧ 1 のとき要約を warn 色**にする。不可のとき「提供なし」 |
  | Global | `Global` | 「世界中 ・ 限定不可」（en: `Worldwide · cannot be limited`）。不可のとき「提供なし」 |

  - 要約はタブを開かなくても読める。タブを 1 つも開かずに 3 レーンの差が分かることがこの AC の目的
  - 国内 N / 国外 M は、そのレーンの全プロファイルの推論先の和集合を `region-notes.json` の `country` で切り分けた件数。起点の `country` が分からないときは件数を出さず「推論先 K」とだけ書く

### AC-015 (既定で選ばれるレーン)
- **Given**: 起点リージョン R でモデル M の行を開く（同じセッションでまだレーンを選んでいない）
- **When**: 詳細パネルを描画する
- **Then**: **使えるレーンのうち最も狭いもの** が選ばれる。優先順は **In-Region → Geo → Global**。3 つとも使えないときは In-Region が選ばれた状態で開く
- **And**: Geo が選ばれたときに複数のプロファイルがあれば、AC-018 の並びの先頭が最初に見える位置に来る

### AC-016 (使えないレーンも開ける)
- **Given**: モデル M が起点 R で In-Region 不可
- **When**: タブを見る / In-Region のタブを選ぶ
- **Then**: そのタブは**淡色**になるが `disabled` にはせず、選べる。開いたパネルには FLOW-001 の図（内側を淡色にしたもの。FLOW-001 AC-003）と「このモデルは＜起点の地名＞で直接提供なし」が出る
- **And**: 使えないレーンでは、価格表に単価があっても**単価の表は出さない**。「この使い方では呼べないため、価格は出していない」旨と、同じ標準の単価を使えるレーン（In-Region が不可で Geo が可なら Geo）があればその名前を出す（2026-10-08 変更。東京の標準の単価は Geo で呼んだときの価格でもあり、In-Region の不可のタブに並べると「提供なしなのに価格がある」と読めるため）
- **And**: **Geo / Global が不可のとき**、そのレーンのパネルは AC-017 の 4 節のうち「指定する ID」を出さない。中身は上から **図 → 推論先 → 価格** の 3 つになる
  - **図**: FLOW-001 の図を 1 枚出し、境界の内側（起点・推論先・記録）をまとめて淡色にする（`.s-off`。FLOW-001 AC-003）。推論先のチップは 1 つも描かない
  - **指定する ID**: **出さない**。対応する推論プロファイルが無く、指定できる ID がそもそも存在しないため。モデル ID を代わりに置くこともしない（In-Region はモデル ID がそのまま指定する ID なので、不可でも AC-017 のとおり出す）
  - **推論先**: 「提供なし」の 1 行だけ（タブの要約と同じ語。AC-014）。Geo の「国内 0」の行も、Global の「範囲: 全商用リージョン」の行も出さない
  - **価格**: 上の And のとおり

### AC-017 (レーンのパネルの中身)
- **Given**: あるレーンのタブパネルを描画する
- **When**: パネルを見る
- **Then**: 上から次の 4 つがこの順に出る（Geo / Global が不可のときだけ「指定する ID」が抜ける。AC-016）

  1. **データの流れ図**: FLOW-001 が定める図 1 枚（Geo で複数プロファイルのときは AC-018）
  2. **指定する ID**: そのレーンで指定する ID とコピーボタン。In-Region はモデル ID、Geo / Global はプロファイル ID
  3. **推論先**: 下記 AC-018 / AC-019 の形
  4. **価格**: **そのレーンの分だけ**（下記 AC-013）
- **And**: 機能の節はレーンのパネルの中には置かない（レーンのパネル群の下に 1 回だけ。AC-023）。4 節の並びと AC-016 の例外は変えない

### AC-019 (推論先の表示)
- **Given**: あるレーンのタブパネルの「推論先」節を描画する
- **When**: 節を見る
- **Then**: レーンごとに次の形になる。**リージョンコードは出さず地名で出す**（コードは REGIONS-001 の行列と FLOW-001 の図の起点ノードで読める）
  - **In-Region**: 起点の地名 1 件。不可のときは「提供なし（＜起点の地名＞では推論プロファイル経由のみ）」
  - **Geo**: 「国内 N」「国外 M」の 2 行に地名を「・」で連ねる。国外の行は warn 色。国外が 0 件ならその行を出さない。節の下に「起点が＜起点の地名＞のときの推論先。**起点が変わると推論先も変わる**」の注記
  - **Global**: 「範囲: 全商用リージョン（国外を含む・限定できない）」の 1 行のみ。個別のリージョンを列挙しない。節の下に「個別のリージョン名は API から取得できないため、図の地名は例示」の注記（D-003、Design FAQ Q6）

### AC-018 (Geo に複数のプロファイルがあるとき)
- **Given**: 起点 R でモデル M に Geo プロファイルが 2 つ以上ある（例: 東京起点の `jp.` と `apac.`）
- **When**: Geo のタブパネルを描画する
- **Then**: プロファイルごとに **図 + 指定する ID + 推論先** の 3 点セットを 1 ブロックとして縦に積む。ブロックの見出しは地理圏名
  - 並びは**狭い順**（`sources[R]` の件数の昇順。同数なら接頭辞の昇順）。東京起点なら `jp.`（2 件）→ `apac.`（8 件）
  - 価格の節はブロックごとに繰り返さず、パネルの末尾に 1 つだけ置く（Geo のプロファイル間で単価は変わらないため）

### AC-013 (レーンごとの価格)
- **Given**: 起点リージョン R でモデル M のレーンのパネルを描画する
- **When**: 価格の節を見る
- **Then**: **種別 × 入力 / 出力** の小さな表が出る。行はそのレーンに対応する種別だけで、`prices.json.byModel[M][R]` から引く（PRICE-001 AC-010）
  - **In-Region / Geo**: 標準 / バッチ / キャッシュ読み / キャッシュ書き / 優先 / Flex のうち R に単価があるものをこの順で（priority / flex しか無いモデルもある。Qwen3 Next 80B の東京）。Geo のとき注記に「Geo の推論プロファイルは標準価格と同じ」を足す
  - **Global**: Global / Global バッチ / Global キャッシュ読み / Global キャッシュ書き（PRICE-001 v4、D-019）。Global のバッチ・キャッシュが 1 つも無いときは注記に「Global 用のバッチ・キャッシュ価格は未収録」を足す（bedrock-mantle の表があるときは「bedrock-runtime の〜」と限る）
  - 長文コンテキストの単価があれば、同じ種別の後ろに「長文コンテキスト」の行を足す。境界のトークン数は価格表に無いので、あるときだけ添える
  - **bedrock-mantle の単価**（`prices.json.byModel[M][R].mantle`）があれば、「bedrock-runtime」と「bedrock-mantle」の見出しを付けて表を 2 つに分ける。値を混ぜない（D-017）
  - **出典**: Runtime の単価が AWS Marketplace の offer から補ったもの（`source.type === "marketplace"`）なら、offer ID 付きの出典を表の下に出す（D-018）
  - 単価が無いときは「この起点リージョンの価格データがありません」の下に、docs のモデルカード（無ければ料金ページ）へのリンクを出す（D-018）
  - 値は USD / 100 万トークン。出力側の単価が無い種別（キャッシュ読み・キャッシュ書き）は「—」
  - 表の下に「USD / 100 万トークン（＜起点の地名＞）。標準価格で、割引・契約価格・無料枠は含まない」の注記
  - そのレーンに対応する単価が 1 つも無ければ、空欄にせず「この起点リージョンの価格データがありません」と表示する
  - SKU・`usagetype`・offer code は出さない（PRICE-001 AC-012）

### AC-023 (機能の節)
- **Given**: 起点リージョン R でモデル M の行を開く
- **When**: 詳細パネルのレーンのパネル群の下を見る
- **Then**: 見出し「機能（Capabilities and Features）」の節が**パネルに 1 回だけ**出る。レーンのパネルごとに繰り返さず、レーンのタブを切り替えても中身は変わらない。中身は上から（FEATURE-001 AC-013）
  1. 機能 × `bedrock-runtime` / `bedrock-mantle` の表。値は表のセルと同じ「✓ 対応」/「✕ 非対応」のピルと「—」（記載なし）で、表の下に凡例を置く（FEATURE-001 AC-018）。行は `features.json` の `features` の順で、どちらかの側に記載がある機能だけ。機能名は ja / en とも docs の英語名のまま
  2. `promptCaching` があれば Prompt caching の表（Explicit 対応 / Min tokens per checkpoint / Max checkpoints per request / Supported TTL / Fields）。見出しは辞書、値は docs の文字列のまま
  3. `computerUse` があれば Computer use の表（Tool type / Beta header）
  4. 公式 docs のモデルカードへのリンク
- **And**: 機能はモデルと接続先で決まり、起点リージョンとレーンには依らない（だからレーンのパネルの外に置く）
- **And** (Error Case): `features.json.byModel` に M が無い、または `features.json` が空のときは、空欄にせず「公式 docs のモデルカードに機能の記載がありません」と表示する。例外で描画が止まらない（FEATURE-001 AC-014）

### AC-020 (選んだレーンはセッション内で覚える)
- **Given**: あるモデルの行で Global のタブを選ぶ
- **When**: 別のモデルの行を開く
- **Then**: そのモデルで Global が使えるなら Global が選ばれた状態で開く。使えないなら AC-015 の既定（最も狭い使えるレーン）に戻る
- **And**: 選択は**セッション内のメモリにだけ**持ち、URL にも `localStorage` にも保存しない（SHARE-001 の Notes と同じ理由: 共有の主目的は起点と条件）

### AC-021 (Error Case: どのレーンも使えない)
- **Given**: 起点 R でモデル M の In-Region / Geo / Global がすべて不可
- **When**: 行を開く
- **Then**: 3 つのタブすべてが淡色になり、In-Region のパネルが開いた状態で「この起点リージョンからは呼べません」と表示される。空のパネルを無言で出さない

### AC-022 (Error Case: 起点が未取得のリージョン)
- **Given**: `fetch-log.json.regions[R].status` が `ok` 以外
- **When**: そのリージョンを起点にする
- **Then**: 表が 0 行になるので詳細パネルは開かれない（TABLE-001 AC-009）。パネル側で `cause` を表示する経路を持たない（D-008）

## UI Description

- 表の行の展開トグル（`aria-expanded` を持つボタン）。開くと行直下に全幅の詳細パネルが挿入される
- 詳細パネルの構造は上から 4 段:
  1. **共通の見出し行**（`div.head-grid`）: モデル ID（コピー可）/ 接続先 `bedrock-runtime` / 接続先 `bedrock-mantle`（あれば）
  2. **レーンのタブ**（`div.lane-tabs`、`role="tablist"`）: 見出しと要約の 2 行。選択中は下線がアクセント色、使えないレーンは淡色
  3. **レーンのタブパネル**: 図 → 指定する ID → 推論先 → 価格
  4. **機能の節**: レーンのタブパネル群の下に 1 回だけ（AC-023）
- 375px では見出し行を 1 列に積み、タブは折り返す。図は横スクロールの入れ物に入る（FLOW-001 AC-NFR-001）
- **「提供状況」節と「推論プロファイル」節はパネルに無い**。前者は REGIONS-001 の行列、後者は将来の「プロファイル」ビューが持つ（D-013）

## Context Boundary

### Inputs
- **From**: TABLE-001 — 展開対象のモデル ID、現在の起点リージョン
- **From**: DATA-001 — `data/models.json`（In-Region 判定）、`data/profiles.json`（`sources`）、`data/region-notes.json`（表示名・`country`・`endpoint`）、`data/mantle.json`
- **From**: PRICE-001 — `data/prices.json`（レーンごとの単価）
- **From**: FEATURE-001 — `data/features.json`（機能の節）
- **From**: FLOW-001 — 各レーンのデータの流れ図
- **From**: I18N-001 — レーン名・要約・節の見出し・注記

### Outputs
- **To**: FLOW-001 — 描画するレーンの種別、起点リージョン、対象プロファイル
- **To**: なし（他コンテキストに状態を渡さない。選んだレーンはセッション内のメモリのみ）

### Dependencies
- **TABLE-001**: 行の展開操作と起点リージョンの現在値
- **DATA-001**: 表示する全データ
- **FLOW-001**: パネルの主役である図
- **REGIONS-001**: 全リージョン横断の提供状況（パネルからは出さないので、読み手をそちらへ案内する導線を持つ）

## 委譲する非機能要件

- **a11y（基本的なキーボード操作性）**: 展開トグルが Tab で到達し Enter / Space で開閉できること、レーンのタブが `role="tablist"` の標準的な矢印キー操作で移動できること、`aria-expanded` / `aria-controls` / `aria-selected` が正しいことを**手動チェック**で確認する。合格基準は「マウスを使わずに 3 レーンの図と要約まで到達できる」
- **セキュリティレビュー: 不要。** 表示のみの静的コンテンツで、扱うデータは AWS の公開情報のみ

## Notes

- 「未取得」と「提供なし」の区別（Design Success Criteria / FAQ Q3）は、v8 以降 **REGIONS-001 の行列**が受け持つ。詳細パネルは「この起点からどう呼べるか」に絞る
- パネルから外した 2 節の行き先: 「提供状況」→ REGIONS-001、「推論プロファイル」（プロファイルごとの 起点 → 推論先 の全行）→ 将来の「プロファイル」ビュー（D-013 で先送り）。どちらも情報を捨てたのではなく、置き場所を変えた
- アカウント固有の `APPLICATION` 型 inference profile は表示しない（Design「What Not」3、技術設計 §8）
- クォータ・ベンチマークはパネルにも出さない（Design「What Not」2・4）。価格は公開価格表の単価だけを出し、試算はしない（Design v2「What Not」1、PRICE-001）
- 図の中の主張は FLOW-001 AC-008 の表に載るものだけ。推定は「推定」と書く（D-014）
