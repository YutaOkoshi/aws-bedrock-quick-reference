# Amazon Bedrock Quick Reference — Design

## Who（誰のため）

**主ペルソナ: 特定のリージョンを起点に Bedrock を使う、世界中の開発者・アーキテクト**

- 自分の国や地域のリージョンを起点に、生成 AI の機能を業務システムに組み込もうとしている
- 顧客や情シスから「データは自国・自地域に留まるのか」「どの国で処理されるのか」を問われる立場にある
- モデルを選ぶたびに公式ドキュメントのモデルカードを一枚ずつ開き、リージョン表を見比べている
- 具体例として作者自身は東京（ap-northeast-1）と大阪（ap-northeast-3）を起点に使う。設計上の既定値はここに置くが、起点はどのリージョンにも切り替えられる

**課題**

- 「このモデルは自分のリージョンで使えるか」と「そこから呼んだとき実際にどこで推論されるか」は別の問いなのに、公式ドキュメントでは同じ場所に並んでおらず、モデルごとにページが分かれている
- 推論先が自分の opt-in していないリージョンにも及ぶことが知られておらず、コンプライアンス上の見落としが起きやすい
- モデル ID と inference profile ID のどちらを指定すればよいかが、試してエラーを見るまで分からない

**副ペルソナ: セキュリティ・コンプライアンス担当者**

- コードは書かないが、開発チームの「このモデルを使いたい」に対し、データ所在の観点で可否を判断する
- 判断材料として、モデルごとの推論先リージョンの一覧を、根拠付きで一目で見たい

**このプロジェクトの出発点**

作者が顧客から「In-Region と Geo は何が違うのか。うちのデータは日本から出るのか」と問われ、その場で答えられなかったことがこのサイトを作る動機になった。答えるのに必要な事実は全部 AWS が公開しているのに、1 か所にまとまっていなかった。

## Why（なぜ今）

- Bedrock の cross-region inference が標準の使い方になり、新しいモデルは地理プロファイルやグローバルプロファイル経由でしか使えないものが増えている。「モデルを選ぶ」ことが「推論先を選ぶ」ことと不可分になった
- 日本やオーストラリアなど、一つの国に閉じるプロファイルが登場し、「自国内で推論できるモデル」という選択肢が現実になった。どのモデルがそれに当たるかを一覧で示せると選定が速くなる
- 公式ドキュメントは最近も構成が変わり、モデル別リージョン表が個々のモデルカードに分散した。横断的に比較できる場所がなくなった
- 先行して作った EC2 GPU インスタンスのリファレンスサイトが、同じ「公式情報を一表に集約する」形で日常的に使われている。同じ体験を Bedrock にも欲しい

## What（何ができるか）

**一つの表で、モデル × リージョン × 推論先が分かる**

- 起点となるリージョンを一つ選ぶと、そこから使える全モデルが一覧になる
- 各モデルについて、次の三つの使い方のどれが可能かが一目で分かる
  - **そのリージョン内で推論する**（In-Region）
  - **同じ地理圏のリージョン群で推論する**（Geo）。どのリージョン群かも同時に表示する
  - **世界中のリージョンで推論する**（Global）
- 使うときに指定する ID（モデル ID か、プロファイル ID か）がそのまま表に出ていて、コピーして使える
- 起点リージョンの接続先（エンドポイント）も同じ画面で確認できる

**推論先を根拠付きで示す**

- 地理圏プロファイルの推論先リージョンは、公式の定義から取ったものをそのまま列挙する
- グローバルプロファイルは「対象リージョンは全世界で、今後増えうる」ことを注記する
- 「情報が取れなかったリージョン」と「提供されていないリージョン」は表示を分け、読み手が誤解しないようにする
- データの取得日と出典を脚注に出す

**画面は 2 つのビューに分かれる**

- **「起点から」**（既定）: 起点リージョンを 1 つ選び、そこから使える全モデルを上の表で見る。絞り込み・推論先の限定・行を開いての詳細はここ
- **「リージョン」**: 起点を選ばず、モデル × 全リージョンの行列を 1 枚で見る。「このモデルはどの国で使えるのか」を横断で確かめるのはこちら。行は同じ並び、列は地理圏でまとめる
- どちらのビューを見ているかは URL に載り、そのまま共有できる

**データの流れを図で示す**

- 行を開くと、使い方（In-Region / Geo / Global）ごとにタブが並び、それぞれに **データがどの境界の内側で処理されるかの図**が出る。タブを開かなくても「国内に留まる」「国内 2 ・ 国外 6」「世界中 ・ 限定不可」の 1 行要約が見える
- 図の中心には **記録は起点に残る**ことを置く。処理されるリージョンが国外に及んでも、CloudTrail・CloudWatch・呼び出しログ・請求・バッチ出力は起点リージョンに残る。監査で最初に聞かれるのはここなので、推論先と同じ図の中で答える
- 図に書く主張は、公式ドキュメントに明記があるものだけにする。明記が無く**推定**で書かざるを得ないもの（モデル呼び出しログの所在）は、画面上でも「推定」と分かる言い方にする

**並び順は編集上の判断として明示する**

- 既定の行の並びでは、よく参照される 2 社（Anthropic・OpenAI）を先頭に固定する。これは事実ではなく**編集上の判断**なので、隠さない。脚注でどの 2 社を固定しているかを書き、プロバイダ名の純粋な昇順にワンクリックで切り替えられ、選んだ並びは URL に載る
- 固定するのは並び順だけで、行を隠したり、判定・価格・絞り込みの結果を変えたりはしない

**探しやすい**

- 提供元（Anthropic、Amazon、Meta など）、入出力の種類（テキスト、画像、音声、埋め込み）、名前の部分一致で絞り込める
- 「この起点リージョンから呼べるものだけ」に絞れる
- **推論先を限定して絞れる。** 「推論先がこの国（またはこの地理圏）の中に収まるものだけ」を指定すると、データ所在の条件を満たすモデルと使い方だけが残る。起点が東京なら「日本国内のみ」、起点がフランクフルトなら「EU 内のみ」といった使い方になる
- 行を開くと、そのモデルを使い方ごとに見られる（上記「データの流れを図で示す」）。全リージョン横断の提供状況は「リージョン」ビューの行列で見る

**価格の目安が同じ行で分かる**

- 起点リージョンでそのモデルを使ったときの標準価格（入力・出力それぞれ 100 万トークンあたり）を一覧に出す
- 世界中で推論する使い方（Global）に別の価格があれば、その場所の表示と並べて出す。「どこで推論するか」と「いくらか」を同時に比べられる
- バッチ・キャッシュ・優先度別などの細かい価格は、行を開いたときに見られる
- 価格は AWS が公開している価格表をそのまま取り込み、取得日を明示する

**もう一つの接続先（Mantle）が分かる**

- 起点リージョンに OpenAI 互換・Anthropic 互換の接続先（bedrock-mantle）があるかと、その URL を、通常の接続先と並べて出す
- 各モデルがその接続先で使えるかを一覧の列で示す。使えるモデルは通常の接続先と食い違うことがあり、Nova のように通常側だけのモデルや、Mantle 側だけのモデルがある
- その接続先では地理圏・世界中への振り分け（cross-region inference）は使えないことを注記する

**誰でも開ける**

- ログイン不要の公開ページ。日本語と英語を切り替えられる
- スマートフォンでも表が読める

## What Not（何をやらないか）

1. **料金の見積もりや請求額の計算はしない。** 載せるのは公開価格表の単価だけで、利用量からの試算やプロビジョニングの費用は範囲外
2. **クォータ・スループット上限は扱わない。** アカウントごとに異なる値をこのサイトで扱うと誤りの元になる
3. **利用者固有の設定は扱わない。** アカウントに紐づくアプリケーション推論プロファイルやカスタムモデルは載せない。載せるのは AWS が提供する公開情報のみ
4. **モデルの性能比較・推奨はしない。** ベンチマークや「どのモデルを選ぶべきか」の助言は範囲外。事実の一覧に徹する
5. **リアルタイム更新はしない。** 取得日を明示したスナップショットを掲載する。今この瞬間の状態は AWS コンソールで確認してもらう
6. **コンプライアンス判断の代行はしない。** 推論先の事実は示すが、「この構成は規制を満たす」といった判断は読み手が行う
7. **Bedrock 以外の AWS AI サービスは扱わない。** SageMaker や Amazon Q は範囲外

## FAQ

**Q1. 公式ドキュメントと何が違うのか？**
公式はモデルごとにページが分かれ、リージョン表もそこに散らばっている。このサイトは起点リージョンを軸に全モデルを横断して並べ、推論先まで同じ行に出す。公式が一次情報で、このサイトはそれを引きやすく並べ替えたもの。

**Q2. 情報はどのくらい信頼できるのか？**
AWS が公開している定義をそのまま取り込み、人の解釈を挟まない。取得日を明示し、出典へのリンクを置く。手作業で補うのはリージョンの日本語名など、意味を変えない範囲だけ。

**Q3. 「取れなかった」と「提供なし」はどう区別されるのか？**
取得に使ったアカウントの制約で情報を取れないリージョンがある。その場合は「データなし」と明示し、「提供されていない」とは別の見た目にする。脚注に取れなかったリージョンを列挙する。

**Q4. データはどのくらいの頻度で更新されるのか？**
手動更新で、新しいモデルやプロファイルが出たタイミングを目安にする。取得日が画面に出るので、古さは読み手が判断できる。

**Q5. 東京起点で「国内だけで推論できるモデル」はすぐ分かるか？**
分かる。起点を東京にし、推論先の絞り込みで「日本国内のみ」を選ぶと、In-Region で使えるモデルと、推論先が国内リージョンだけのプロファイルだけが残る。同じ操作を任意の国・地理圏で行える。

**Q6. グローバルプロファイルの推論先はなぜ列挙されないのか？**
AWS の定義上、グローバルは「対応する全リージョン」であり、一覧が固定されていない。事実に反する列挙をするより、そう注記する方が正確。

**Q7. モデル ID とプロファイル ID のどちらを使えばよいかは分かるか？**
分かる。In-Region が可能なモデルはモデル ID を、Geo / Global で使うモデルはそのプロファイル ID を表に出す。そのままコピーして使える。

**Q8. 自分のアカウントで有効化していないリージョンに推論が飛ぶことはあるのか？**
ある。AWS の説明では、プロファイルの推論先には opt-in していないリージョンも含まれうる。このサイトはその推論先をそのまま表示するので、事前に気づける。

**Q9. 日本以外の利用者も使えるか？**
使える。起点リージョンは全リージョンから選べ、推論先の絞り込みも任意の国・地理圏で指定できる。表示は日本語と英語を切り替えられ、既定は閲覧環境の言語に合わせる。

**Q10. スマートフォンで見られるか？**
見られる。表は横スクロールで崩れずに読めるようにする。

**Q11. 誰が保守するのか？**
個人プロジェクトとして作者が保守する。更新手順は再現可能にしておき、誰でも同じ結果を得られるようにする。

**Q12. 誤りを見つけたらどうすればよいか？**
公開リポジトリの Issue で受け付ける。出典との食い違いが分かる形で報告してもらう。

**Q13. 価格はどこから来て、どのくらい正確か？**
AWS が公開している価格表（Price List）をそのまま取り込む。表示は標準価格の単価で、取得日を明示する。割引・契約価格・無料枠は反映しない。正確な請求額は AWS の料金ページと請求で確認してもらう。

**Q14. Mantle とは何か。通常の接続先と何が違うのか？**
同じ推論基盤に対する、OpenAI 互換・Anthropic 互換の API を持つもう一つの接続先。使えるモデルとリージョンが通常の接続先と異なり、地理圏・世界中への振り分けは使えない。価格も Price List では別の SKU で、通常の接続先と値が違うモデルがある（2026-10-08 に Qwen3 Next 80B で確認、D-017）。このサイトはその違いを一覧で見えるようにする。

**Q15. ある特定のリージョンの情報だけ欲しい場合、ページを分けるのか？**
分けない。起点リージョンの選択で同じ表を切り替える。URL で起点リージョンを共有できるようにする。

## Success Criteria

**定量**

- 起点リージョンを選んでから、任意のモデルの In-Region / Geo / Global の可否と推論先を確認するまでの操作が **3 回以内**（選択、絞り込み、行を開く）
- 掲載するモデルとプロファイルの定義が、取得日時点の AWS 公開情報と **100% 一致**する（人の解釈による差分ゼロ）。更新のたびに機械的に検証できる
- 取得できなかったリージョンが **必ず脚注に列挙**され、「提供なし」と混同される表示が **ゼロ**
- スマートフォン幅（375px）で表が横スクロールで読め、レイアウト崩れが **ゼロ**
- 公開後 3 か月で、作者以外からの参照（検索流入または共有）が **月 50 回以上**

**定性**

- 「自分のリージョンから使うと実際にどこで推論されるか」を、公式ドキュメントを開かずにこのサイトだけで答えられる
- 「推論先を自国内に限る」という条件で候補を絞る操作が一度の選択で済む
- 「このモデルを東京で使うといくらか」「世界中で推論すると安くなるか」が同じ行で分かる
- コンプライアンス担当者が、開発者の説明なしにこのサイトを見て推論先を理解できる
- 先行の EC2 GPU リファレンスと同じ感覚で使え、見た目と操作に違和感がない
